# QC Plan: Employee Salary Management (full codebase)

**Health:** Good. 230 passing tests (shared 32, server 111, web 87). They test behaviour through real HTTP + in-memory SQLite and real routes + MSW, use role/label queries and concrete assertions, and are well isolated. The layers are clean: no file-level cycles, `db` is passed explicitly, `shared/` has no dependencies.
**What's already strong (don't duplicate):** paging/search/filter/sort, CRUD incl. 409 email, codes never reused, concurrent adds, import validation + all-or-nothing + 10k rows, export, insights, all main web flows (list, add/edit/delete, bulk delete, import, export, URL state, layouts).
**Where the risk is:** what happens at the edges. That means oversized or failed requests, duplicate keys under a race, and duplicate data in one import file. These are the paths that could corrupt data or leak internals, and they are currently untested.

Analysis method: text-based pattern matching (based on the review outputs; key claims were checked by reading `error-handler.ts`, `app.ts` and `country-repository.ts`).
Caveat: 30 commits, 1 author, ~2 days. "Churn" mostly reflects the order things were built, so risk was weighted more heavily than the hotspot score.

### Test-hygiene fixes (do while touching the files, ~15 min total)
- `web/src/utils/format.test.ts` says "every time zone" but never sets TZ. Either run the cases under 2 TZs (`process.env.TZ` in vitest config/env) or rename the test. Right now it gives false confidence.
- `EmployeesPage.test.tsx:235`: `handlers.slice(0,1)` depends on handler order. Use a named handler.
- `ExportEmployees.test.tsx` assigns `URL.createObjectURL` directly. Use `vi.spyOn(...)` plus `restoreAllMocks`.
- `import.test.ts:99`: add `%s` to the `it.each` title so failures name the case.

## Refactors these tests motivate (max 3)

1. **Translate the country PK violation in `insertCountry`** (required by item 2). Reuse the existing duplicate-value detection from `employee-repository` and don't write a new one. This makes the race-condition handling the same in both features.
2. **One import-wide "country must be set up" rule** (motivated by item 3). `import-service` calls `country-repository` directly and repeats the rule with a different message than `country-service.requireCountryCurrency`. Add a bulk `getCurrencyByCountry` to `country-service` with one message and use it from both. This also removes a cross-feature call into a repository.
3. **Build the export query from the schema, not by hand** (motivated by item 8). `ExportEmployeesDialog` copies the filter fields one by one, so a new filter would be silently dropped from exports. Use `employeeExportQuerySchema.parse(query)` and pass `totalItems` as a prop instead of calling `useEmployeeList`, which also breaks the export↔employees folder cycle. Add one test: "export uses the active filters" with every current filter set.

## Consciously skipped (and why)

- **Shared employee-record module** for the 3 copies of the column list (repository, import-repository, seed). This is a real smell, but it's a moderate refactor late in the project. The existing import create/update tests already catch column-order bugs.
- **`server/src/vercel.ts` startup/503 paths.** This is deploy glue, checked by hand on the live deploy. Testing it would mean mocking env and module state for little return.
- **Schema-validated fixture factory for `web/.../test-data.ts`.** The fixture does drift with the schema, but TypeScript already flags shape changes. Nice to have.
- **Fake API sort support in web test-data.** Sorting is tested on the server, and the web test only needs to check that the URL/param is sent. Instead, add a one-line comment documenting the limitation.
- **Services importing HTTP errors** (inner layer depending on outer). Low urgency. Moving to domain errors plus a mapping layer adds indirection that a project this size doesn't need yet.
- **Dialog focus/reopen edge cases, `AppErrorPage`, `useScreenSize` live change, color-mode storage failure, takeaways ties.** Low risk polish. The main paths are already tested.
- **Duplicated USD-conversion SQL, country-option builders, invalidation helper, `today()` injection, fixtures location.** These are two copies each, or cosmetic. Extract on the third occurrence.
- **Unit-testing the `DuplicateValueError`→409 race branch in import.** Item 3 covers the real-world paths. Faking a mid-transaction race costs more than it proves.
- **bootstrap file-vs-remote client choice, `scripts/build-vercel.mjs`.** Nitpicks, and the build script checks itself.
